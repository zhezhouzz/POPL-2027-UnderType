### Review #106A

#### Overall merit

B. OK paper, but I will not champion it

#### Reviewer expertise

Y. Knowledgeable

#### Paper summary

The paper unifies safety and reachability reasoning during typing in a functional language. Variables in the context are read angelically or demonically depending on whether they are used for must- or may-reasoning. Dependency between variables makes reachability reasoning more complex, which requires two different constructors over typing contexts: "∗" to concatenate disjoint environments, and "," to concatenate environments with dependent variables. Correspondingly, there are two kinds of function types: one for functions whose argument depends on its context, and another for functions whose argument does not. The paper presents a function calculus with datatypes, and then extends it with nondeterminism via a gen operator that generates random values. Type soundness is proven using a type denotation, together with a fundamental theorem showing that the denotation of a well-typed term is included in the denotation of its type.

#### Strengths

I did like the approach of having angelic and demonic modalities in a single language, rather than treating safety and reachability in separate frameworks. The paper is well written through the first half, and the large number of examples makes it a nice read. It also includes case studies that show how the system is meant to be used.

#### Weaknesses

- Motivation. The only motivating example in the introduction is Peano division. The introduction claims that prior work does not provide a "general type-based reachability framework" (p. 1), but it is never made clear what this generality amounts to, or what specifically previous work fails to handle.

- Practicality. It is not clear whether this is implementable. It seems to be a nice theoretical result, but its practical use is left open.

- Presentation. I can follow the paper just fine up to Sections 3 and 4, but from there on the formalism relies on some symbols and definitions that are not in the paper. This matters most at the argument for choosing ⊑ as the Kripke order, which appears to be where the main technical contribution lies (⊆ and ⊇ are not enough). I could not follow this argument as written, and since the demonic and angelic clauses of Definition 4.3 rest on it, I was not able to check the core of the paper.

- Examples do not match the rules. In several places the worked examples do not follow from the rules as stated: the second example on p. 13 does not type its first branch, although the first premise of T-Match requires it; the context on p. 13 carries a binding for y that is not needed; Figure 6 (b) appears to require switching a demonic parameter to angelic, which §2 disallows; and the claim on p. 23 that the base cases of merge type-check does not hold, since nothing establishes that the inputs are sorted.

### Review #106B

#### Overall merit

B. OK paper, but I will not champion it

#### Reviewer expertise

X. Expert

#### Paper summary

This paper develops a simple refinement type system that supports reasoning about (in)dependence between free variables in the context, as part of assigning types to program expressions. This allows the system to state and prove properties of safety (as usual) and reachability, i.e. that a given expression can non-deterministically evaluate to every value in a given type. A semantics is given for types as formulas in a bunched implication logic, with the meaning of a given formula as a set of sets of environments, and the type system is shown to be sound with respect to it. The proof is mechanised in Rocq.

#### Strengths

- Viewing angelic and demonic choice as a resource that can be reasoned about using modalities in a bunched type system is a nice idea.

- I think the idea is developed into a quite elegant type system, with most of the key definitions being conceptually quite simple, but allowing for complex reasoning.

- The soundness result is machine checked.

#### Weaknesses

- It seems that a lot of heavy lifting when using the type system is done by the subsumption rules, which require unpacking all the definitions of the semantics and are thus a little unwieldy.

- There is a restriction that all well-typed terms are total, and to type a recursive function: the first argument x must be of base type, its refinement type must be a demonic type, the refinement type of the recursive call must be predicated on it's argument decreasing relative to x (and therefore be entangled with x). Thus, what can be asserted about, e.g., unary recursive functions seems limited.

- Some relationship with previous work is unclear.

#### Comments for authors

The main premise of this paper, that angelic and demonic non-determinism can be viewed as a resource and reasoned about using a bunched type system, is neat, and the authors do an excellent job, through many simple examples, of motivating how the idea plays out in terms of the sorts of judgements that can be stated and proven.

However, I don't quite follow the first interesting example, on line 82. Isn't this judgement provable? It only uses the (usual) T-Lam and T-AppFun rules and the context-less T-Var rule. Here, it seems from the definition of the semantics that the context:
x:[v:nat∣v>0],f:[v:nat∣v>0]→[v:nat∣v>0]

subsumes both the context just containing the binding for x (when restricted to just the variable x) and the context just containing this binding for f (when restricted to just the variable f). Thus, the typing of x can be dropped to enable the use of the T-Var rule at the f leaf of the derivation and the typing of f can be dropped to enable the use of the T-Var rule at the x leaf of the derivation. Isn't it rather that the supposed counterexample doesn't satisfy the judgement x:[v:nat∣v>0]⊢λy.x−y:[v:nat∣v>0]→[v:nat∣v>0] and thus is not an appropriate input?

In any case, this illustrates the point that the subsumption rules, which are just delegated to the model, are doing a lot of work. This can also be seen in the fact that the typing rules barely mention the modal base type comprehensions, all the reasoning about angelic and demonic choice really comes through subsumtion. It is already the case that in other refinement type systems, e.g. Liquid Types, a lot of emphasis is placed on the subsumption rule in order to get reasoning done, and here it is even more crucial since it is the mechanism by which to achieve weakening, which is essential when dealing with the entangled variables. So, although I think the type system seems very elegant, it partly dodges the interesting question of fixing reasoning principles for angelic and demonic modal types, and it is not clear how much of it is novel compared to previous work on bunched typing. Incidentally, although in, e.g. Liquid Types, subsumption is in part delegated to the model, but, in my opinion, the model there is much simpler, and thus one can reason about subsumption without having to carefully unpack a lot of definitions.

The case studies of Section 6 are helpful in helping to imagine how the system may potentially be used. However, I did not follow the first example in Figure 6(a). If the two inputs to f are allowed to be entangled, isn't it possible to supply an input y that depends on x in such a way that whenever x=0, y>10 (although both can, say, reach any non-negative integer)? For this pair of inputs, the then branch will be taken whenever x=0 and the else branch whenever x!=0, and thus, contrary to its specification, the function will never output 1.

The incorrectness example seems to require typing the recursive merge function with a type that violates the requirements on the type of fixpoints (e.g. the first argument must be a demonic base type and the left hand side of a "normal" arrow). Maybe this type can be obtained by subsumption? Generally, the restrictions on the use of recursive functions seem rather limiting. It is not clear to me what kinds of interesting angelic properties can be asserted for unary recursive functions. Also, as far as I know, there is no similar restriction to total functions in other call-by-value refinement type systems, such as Liquid Types. On the other hand, it seems clear that the system can be an alternative to Zhou et al's coverage checking type system.

Finally, I wonder what is the relationship with the POPL'2017 paper of Hiroshi Unno, Yuki Satake and Tachio Terauchi named "Relatively Complete Refinement Type System for Verification of Higher-Order Non-Deterministic Programs" (https://doi.org/10.1145/3158100). If I understand correctly, their system also allows for reasoning about safety and liveness within a single refinement type system. They have 4 modalities that can be applied to any refinements of any underlying type (not only base type refinements). In particular, their {v:b∣ϕ}∀∀ seems to express this paper's {v:b∣ϕ} and their {v:b∣ϕ}∃∃ seems to express this paper's [v:b∣ϕ]. However, I don't know whether they can express a notion of independence or what they lose if they can't.

#### Specific questions to be addressed in the author response

- Please could you clarify any misunderstandings that I have with the examples mentioned in my review.

- Please could you explain in a little more detail the novelties of the type system in Figure 4 (e.g. compared to previous work on bunched typing), if we leave aside the subsumption rules.

- Please could you comment on the relationship of your work with the POPL'17 work of Unno, Satake and Terauchi.

### Review #106C

#### Overall merit

A. Good paper, I will champion it

#### Reviewer expertise

Y. Knowledgeable

#### Paper summary

This paper presents a type system for higher-order programs, with both overapproximating and underapproximating refinement types, and its denotational semantics.
To mediate subtle interactions between angelic and demonic choices, which are related to under- and over-approximation, respectively, bunched typing is used. The problem is that the values of different variables may have a co-relation (or the paper calls it "entanglement"), which complicates reasoning about reachability. By using bunched typing, it is possible to express no-corelation and may-corelated between two typing contexts.
As a result, there are two kinds of function types: one that takes an argument that must not be related to the values in the context and the other that takes an argument that may be related to the values in the context.

The target language is a call-by-value lambda calculus with inductive datatypes, recursion, and nondeterministic choice. In addition to the two kinds of refinement types and dependent function types, it has intersection types and a kind of union types, which mean "both disjuncts are reachable by angelic choice".

The denotational semantics of types is given via context logic, which is an extension of BI with modality to represent demonic and angelic choices and can describe properties about a set of environments (of the same domain). Finally, the type system is shown to be sound using this machinery.

#### Strengths

- A type system for a higher-order language with recursion and nondeterminism to reason about both safety and reachability. While overapproximation is more traditional and used to achieve safety, underapproximation is related to reachability properties. However, mixing the two disciplines in a single framework is very tricky, as the paper discusses. This work overcomes the problem by using bunched typing to keep track of the corelation between variables, as far as I know, for the first time.

- A novel application of bunched typing. Once one understands that the difficulty stems from co-relation/entanglement between variable values in the context, the use of bunched typing may sound straightforward because it has been used for phenomena related to "separation". Nevertheless, this seems like a new application of the idea of separation.

- Definitions and proofs are fully mechanized in Rocq.

- Writing is clear.

#### Weaknesses

- Algorithmic aspects of the type system (decidabiity/complexity) are not discussed. As a result, it's not clear how it can be applied to automated reasoning. (Perhaps, it's more of one direction for future work, rather than a weakness.)
